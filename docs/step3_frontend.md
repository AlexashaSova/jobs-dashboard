# Крок 3 — фронтенд на React + ECharts

Мета кроку: інтерфейс дашборду, який ходить у FastAPI, показує 25 віджетів із фільтрами, має темну й світлу тему, а в production віддається самим FastAPI (один сервер, один порт, один `docker compose up`).

Передумова: крок 2 завершено — `/api/health` показує `status: ok`.

---

## 0. Як це працює

```
браузер
  │  http://localhost:5173  (dev)      або  http://localhost:8000  (prod)
  ▼
React-застосунок (frontend/src)
  │  fetch("/api/widgets/kpi?months=2024-04")
  │  ├─ dev:  Vite перекидає /api → localhost:8000 (vite.config.js → proxy)
  │  └─ prod: той самий сервер, бо FastAPI віддає зібраний dist/
  ▼
FastAPI → ClickHouse → JSON → ECharts малює
```

Ключова ідея така ж, як у бекенді: **фронтенд не знає про SQL.** Він знає лише список віджетів (`src/charts/specs.jsx`): для кожного — який ендпоінт запитати і як перетворити рядки на графік. Додати графік = один SQL-файл у `sql/queries/` + один запис у `specs.jsx`.

Про «згенеровано ШІ»: цей інтерфейс справді згенеровано мною (Claude) за контрактом з `/api/widgets` і твоїми відповідями про стиль. Так і напиши в README — це чесно і це саме те, що ти планувала показати.

## 2. Файли фронтенду

Розпакуй архів у корінь проєкту:

```
frontend/
├── package.json          ← залежності й команди (npm run dev / build)
├── vite.config.js        ← проксі /api → localhost:8000
├── index.html            ← єдина HTML-сторінка; підключає шрифт і main.jsx
└── src/
    ├── main.jsx          ← точка входу: монтує <App /> у #root
    ├── App.jsx           ← каркас сторінки: шапка, фільтри, розділи
    ├── styles.css        ← усі стилі + токени тем (CSS-змінні)
    ├── api.js            ← усі запити до бекенду в одному місці
    ├── hooks/
    │   ├── useWidget.js  ← завантажує дані віджета, перезавантажує при зміні фільтрів
    │   └── useTheme.js   ← перемикач теми + читання кольорів для графіків
    ├── components/
    │   ├── Header.jsx    ← назва, статус API, кнопка теми
    │   ├── FilterBar.jsx ← панель фільтрів (липка, завжди зверху)
    │   ├── MultiSelect.jsx ← випадаючий список з чекбоксами
    │   ├── KpiStrip.jsx  ← ряд ключових цифр
    │   ├── ChartCard.jsx ← панель одного графіка: заголовок, стани, графік
    │   └── EChart.jsx    ← обгортка над ECharts (створити, оновити, resize)
    └── charts/
        ├── specs.jsx     ← ГОЛОВНИЙ ФАЙЛ: опис усіх 25 віджетів і розділів
        ├── common.js     ← спільні шаблони: бари, donut, осі, легенда
        └── format.js     ← форматування чисел, грошей, дат

backend/app/main.py       ← оновлено: віддає frontend/dist у production
backend/app/config.py     ← оновлено: шлях до frontend/dist
backend/app/db.py         ← оновлено: виправлення для паралельних запитів (див. нижче)
backend/Dockerfile        ← оновлено: збирає фронтенд і бекенд в один образ
.dockerignore             ← новий: що не копіювати в Docker-образ
```

Три файли бекенду **замінюють** твої. Особливо важливий `db.py`: дашборд запитує 25 віджетів одночасно, а старий клієнт відкривав одну «сесію» ClickHouse і на паралельні запити відповідав помилкою `Attempt to execute concurrent queries within the same session`. Одна опція (`autogenerate_session_id=False`) це лікує.

### Як влаштований інтерфейс

**Потік даних.** `App` тримає один об'єкт `filters` (місяці, рівні, типи, has_desc, has_skills). Він передається у `FilterBar` (щоб змінювати) і в кожну `ChartCard` (щоб запитувати дані). Коли ти змінюєш фільтр, React перерендерює всі картки, кожна через `useWidget` робить новий запит зі своїми параметрами — і графіки оновлюються. Попередній незавершений запит скасовується (`AbortController`), щоб швидкі кліки не давали «застарілих» відповідей.

**Теми.** У `styles.css` усі кольори — CSS-змінні (`--ink`, `--surface`, `--c1…--c8`). Тема перемикається одним атрибутом `<html data-theme="dark">`, а `readChartTheme()` читає ті самі змінні й передає їх у ECharts, тому графіки перефарбовуються разом зі сторінкою. Вибір зберігається в `localStorage`.

**Візуальний стиль.** Строгий, «звітний»: один шрифт (IBM Plex Sans з табличними цифрами), панелі розділені лініями сітки замість тіней і карток, стримана палітра (navy, teal, slate), кольори несуть значення (teal = remote, bronze = гроші). Розділи мають заголовок і одне речення-пояснення — це і є структура сторінки.

**Стани.** Кожна панель уміє показати «Loading…», помилку з текстом від бекенду і «No postings match the current filters» — це важливо для дашборду з фільтрами, бо порожній результат — нормальна ситуація.

## 3. Запуск для розробки

Мають працювати база й бекенд (крок 2). У **новому вікні термінала**:

```bash
cd frontend
npm install        # один раз, ставить залежності в node_modules/ (~1–2 хв)
npm run dev
```

Vite надрукує адресу — відкрий **http://localhost:5173**. Побачиш дашборд із живими даними. Зміни будь-який файл у `src/` — сторінка оновиться сама, без перезавантаження.

Що подивитись:

1. Перемикач теми у шапці.
2. Фільтр «Months» → обрати один місяць → усі цифри й графіки змінюються, у панелі фільтрів з'являється «N postings match».
3. «Has description → No» — гарний тест: даних мало, деякі панелі покажуть «No postings match».
4. Наведення на будь-який графік — підказки з деталями (медіана зарплати, % remote тощо).
5. Звузити вікно браузера — сітка перебудовується у 2 і 1 колонку.

Якщо всі панелі показують `Couldn't load: 502` — бекенд не запущений або впав; подивись його термінал.

## 4. Як додати новий графік

Це те, що варто вміти пояснити на співбесіді.

1. Написати `sql/queries/25_my_widget.sql` з тими ж рядками-фільтрами, що в інших (скопіюй `WHERE (...)` з будь-якого файлу). Перший коментар — опис, `-- Віджет: ...` — тип графіка.
2. Перевірити його: `./scripts/run_query.sh my_widget`.
3. Бекенд підхопить файл сам (при `--reload` — одразу). Перевір `/api/widgets/my_widget` у `/docs`.
4. У `frontend/src/charts/specs.jsx` додати запис:

```jsx
export const myWidget = {
  widget: "my_widget",            // назва файлу без номера
  title: "Заголовок панелі",
  subtitle: "Одне речення, що тут показано.",
  span: 6,                         // ширина: 12 = весь рядок, 6 = половина, 4 = третина
  build: (rows, t) => hbar(t, rows, { cat: "category_col", val: "postings" }),
};
```

і додати `myWidget` у масив `charts` потрібного розділу в `SECTIONS`.

`hbar` і `donut` з `common.js` покривають половину випадків. Для інших — пиши `option` ECharts руками: у документації https://echarts.apache.org/examples/ є приклад на кожен тип графіка, який можна скопіювати й підставити свої `rows`.

## 5. Production: один сервер

У dev фронтенд і бекенд — два процеси на двох портах. Для «клонував і запустив» це незручно, тому в production фронтенд збирається в статичні файли, а FastAPI віддає їх сам.

```bash
cd frontend
npm run build      # створює frontend/dist/ (HTML + один JS + один CSS)
```

Перезапусти бекенд — і **http://localhost:8000** покаже дашборд. `main.py` перевіряє, чи існує `frontend/dist`, і якщо так — монтує його на `/` (після всіх `/api/...`, щоб не перекрити API).

`frontend/dist/` у `.gitignore` — це артефакт збірки, у репозиторій він не йде.

### Docker: усе разом

`backend/Dockerfile` тепер двоетапний: перший етап на образі Node збирає фронтенд, другий на образі Python ставить бекенд і забирає з першого готовий `dist/`. У фінальному образі нема Node — він потрібен лише для збірки.

```bash
docker compose up -d --build
```

Через пару хвилин **http://localhost:8000** — повний дашборд із одного контейнера + база в другому. Це та команда, з якої починається README.

Документація: multi-stage builds https://docs.docker.com/build/building/multi-stage/

## Типові помилки

| Повідомлення | Причина | Що робити |
|---|---|---|
| `zsh: command not found: npm` | Node не встановлено або термінал не перезапущено після інсталяції | встановити з nodejs.org, відкрити новий термінал |
| `npm ERR! ... EACCES` | проблеми з правами у глобальній папці npm | нам глобальні пакети не потрібні; переконайся, що ти в `frontend/` і запускаєш `npm install` без `-g` |
| усі панелі: `Couldn't load: 502` | бекенд не запущений | `cd backend && uvicorn app.main:app --reload --port 8000` |
| панелі: `ClickHouse error: ... concurrent queries within the same session` | не замінено `backend/app/db.py` | скопіювати новий `db.py`, перезапустити бекенд |
| порожня сторінка на `:8000`, а `:8000/docs` працює | `frontend/dist` не існує | `cd frontend && npm run build`, перезапустити бекенд |
| `Port 5173 is in use` | інший Vite уже запущений | закрити його або `npm run dev -- --port 5174` |
